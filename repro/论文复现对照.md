| Adam，cosine annealing，起始 lr 0.001，"reset every 50 epochs with gradual decay" | `CosineAnnealingWarmRestarts(T0=50, T_mult=2, eta_min=1e-7)`，每 epoch step 一次 | 🟡 "reset every 50" 与 T_mult=2 不能同时成立；按释放版实现为倍增周期（重启点 50/150/350/750/1550） |
| "10-epoch warm-up phase with a fixed learning rate of 1e-6" | `engine.py:115 run_warmup()` + 官方 `LossWarmup` 同构的三项 Charbonnier 组合 + 双头 | ✅ 产物 `ckpt/model_warmup.pkl`，日志前 10 行为 `warmup` |

| ❓ `W_learn` 初始化 | 官方 `utils_IWO.py` 用 `xavier_normal_`（会扰动迁移过来的 W_pre），我们**置零** | 按 Eq.1 字面实现；这是我们有记录的最大一处主动偏离 |
| §3.5 LVW 损失（Eq.7–10） | 两版都实现：`losses.py:23 LVWOfficial`（release 的 `OutlierAwareLoss`：带符号残差、按 (batch,channel) 统计、std/√2）与 `:34 LVWPaper`（Eq.7–10 字面：先取 L1 幅值） | ✅ 用 official 版才对上作者权重 |

## 5. 从零训练（本文档的核心进行中项）

**阶段一：10 warmup + 1000 epoch，已完成**（`runs/lolv1_stage1_190523`）

| 项 | 数值 |
|---|---|
| best val PSNR（看板口径：逐通道、不 clip） | **22.6875 @ep579** |
| best val PSNR（**论文口径**：标准 RGB、clip） | **22.3685 dB**（口径差实测 0.319 dB） |
| 距论文最终 23.62 | **−1.25 dB**（但这只是半个训练） |
| 速率 | 中位 27–35 s/epoch（阶段一全程 30 s） |
| 横向对照 | 已高于论文 Table 1 的 SYELLE 21.03、DDNet 21.82；距 Adv-LIE 23.02 差 0.65 dB（对方 238.6 K 参数） |

**🔎 独立复现了论文的立论前提**：论文 §3.2 说紧凑网络"leading to **stagnation in later training stages**"、
"adjusting hyperparameters often results in **marginal improvements**"。我们的阶段一实测：

- best 定格在 **ep579**，之后 **421 轮再未刷新**；
- 按余弦周期切分，每周期 best 递增后掉头：19.817 → 20.908 → 21.912 → **22.687** → 22.225；
- 刷新 best 的轮次全部集中在重启点附近（ep51/159/228/240/387/505/579）。

这正是 IWO 要解决的问题，等于我们用一次独立训练验证了 Fig.10 蓝线的形态。

**阶段二：IWO 1000 epoch，进行中**（`runs/lolv1_stage2_iwo_181058`）

| 项 | 数值 |
|---|---|
| 起点权重 | `lolv1_stage1_190523/ckpt/model_best.pkl`（22.6875 那份）✅ 已核对 `iwo_transfer.json` |
| 交接 | 7 个 W_learn 槽、全部置零、7 个 conv_out 冻结 |
| 进度 | ep343 / 1000（22:0x 实测），中位 34 s/epoch，预计 **09-28 04:15** 完成 |
| 当前 best | 22.294 @ep325（**尚未超过阶段一的 22.6875**） |
| 同相位对照 | ep1–110 全程优于阶段一同期：Δloss −0.06~−0.27、ΔPSNR +1.6~+3.1 dB |
| ⚠️ 归因警告 | 上述增益主要来自"从好起点重新高温训练"，**不等于 IWO 的功劳**；ΔPSNR 已在收窄（ep50 +2.62 → ep80 +0.07） |

**判据（提前写死，避免事后找解释）**
1. 阶段二必须刷新 **22.6875（看板口径）/ 22.37（论文口径）**，否则"两阶段+IWO 有净增益"不成立；
2. 要归因给 IWO，必须跑**无-IWO 对照组**（同起点、同 1000 轮、同调度，只是不加 W_learn）——对应论文 Table 4 的 `MBRConv (No IWO)` 行；
   ⏳ **已排队**：`scripts\queue_control.cmd`（pid 见 `logs\queue.log`）每 60 s 探测一次，阶段二进程退出后（≈04:16）自动起
   `configs\lolv1_ctrl_noiwo.yaml`，从 `runs\lolv1_ctrl_noiwo\ckpt\state_last.pt`（ep1000、调度器 T_cur=250）续跑到 ep2000，
   指标行与阶段一的 1010 行拼在同一 `metrics.jsonl`，所以曲线是连续的 1→2000。按阶段一 27 s/ep 估 **09-28 12:00–12:45 出全曲线**；
   取消：`echo.> logs\queue.cancel`。CPU 试跑已验证续跑点正确（`continuing at epoch 1001`）。
3. 最终数字与 23.62 比较时，两边都必须用**标准 RGB PSNR + clip**。
4. Fig.10 那种 loss 曲线不能直接跟论文比：我们的 `train_loss` ≈99% 是 PSNR 项（见 §7 第 4 条）。
   从本次改动起，`MobileIELoss.forward_parts()`（`src/mobileie/losses.py`）会把 **loss_pixel / loss_cos / loss_psnr_term**
   三项分别写进 `metrics.jsonl`，对照组与后续 run 都能按项对比；已结束的 stage1/stage2 进程用的是旧代码，没有这三列。

## 7. 论文没写 / 我们做的假设（完整清单）

1. **PSNR 口径**：论文 23.62 = 标准 RGB PSNR；release `main.py` 的逐通道平均会高 **0.319 dB**（实测）。两套都实现，报告里分行写。
2. **LPIPS 主干**：Table 1 的 0.198 是 AlexNet；同一批图用 VGG 是 0.293。
3. **FPS 列的真实含义**：`FPS = 1/GPU延迟`（12 行里 11 行吻合），不是手机帧率；手机对应的是 SoC 列。
4. **训练目标**：正文只写 LVW，实际 release 还含余弦项与 2×可微 PSNR 项。
5. **IWO 的 W_learn 初始化**：官方 xavier_normal_ vs 我们置零（按 Eq.1 字面）。
6. **余弦调度**："reset every 50 epochs" 与 T_mult=2 冲突，按倍增周期实现。
7. **参数量系统性 +0.7% 偏移**：LLE/ISP 两个模型都是 +0.028 K，怀疑通道或 PReLU 统计口径，未定位到具体来源。
8. **UIEB 测试集构成**：本镜像 90 张 ≠ 官方 60 张（已排除分辨率解释）。
9. **ISP 延迟测速形状**：未披露，我们的 0.428 ms 与论文 1.020 ms 不可比。
10. **MACs 统计口径**：未披露，我们只数 Conv2d。
11. **ZRR 混合位深**：RAW 张量存在 10/12-bit 混排，验证过不会截断成 255（判据从"逐张比对"改成"饱和检测"）。
12. **文件枚举顺序**：官方用 `os.listdir`（不确定序），我们排序以保证可复现。
