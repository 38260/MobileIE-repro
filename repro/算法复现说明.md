## 1. 核心算法拆解

MobileIE 的立足点是一句话：**把「训练时的表达力」和「推理时的算子形状」彻底解耦**。
训练图是一个多分支、带 BatchNorm、超完备通道数的图；推理时整张图被**代数折叠**成
6 层普通卷积。因此它的参数/算力账本有两套，复现时也必须分开验证。

### 1.1 拓扑（`channels=12`, `rep_scale=4`，取自官方 `config/lle.yaml`）

```
退化图 x (3×H×W)
  ┌─ head ─────────────────────────────────────────┐
  │ MBRConv5(3→12) → PReLU(12) → MBRConv3(12→12)   │ → FST:  Scale·(f⊙f) + bias
  ├─ body ─────────────────────────────────────────┤ → FST:  MBRConv3(12→12)
  ├─ HDPA ─────────────────────────────────────────┤   Ag = σ(conv1x1(AvgPool(F)))
  │                                                │   Al = σ(conv1x1(Max_c(Ag⊙F)))
  │                                                │   F̂  = Ag ⊙ Al ⊙ F
  └─ tail ─────────────────────────────────────────┘   MBRConv3(12→3) → 增强图
     （tail_warm: MBRConv3(12→3) 只存在于训练图，供预热阶段重构退化输入）
```

各 MBRConv 的分支构成（官方 `model/utils.py`）：

| 模块 | 分支（每支输出 `C×rep_scale`=48 通道，各带一条并行 BN） | concat 后 | conv_out |
|---|---|---|---|
| `MBRConv5` | 5×5 / 1×1 / 3×3 / 3×1 / 1×3 | 480 通道 | 1×1, 480→12 |
| `MBRConv3` | 3×3 / 1×1 / 3×1 / 1×3 | 384 通道 | 1×1, 384→12 |
| `MBRConv1` | 1×1 | 96 通道 | 1×1, 96→12 |

> 关键点：**每条分支都并行接了一个 BN**（`utils.py:11-29`）。论文 §3.2 明确说这是与
> RepVGG/DBB 的差异——BN 在 IE 任务上虽被普遍认为无用，但它是唯一能被「吸收进卷积核」
> 的非线性来源，所以保留；而 `conv_out` 那个 1×1 压缩矩阵则负责把 10 路多尺度特征
> 映射回 C 通道，它同时也是 IWO 的作用对象。

### 1.2 重参数化折叠（Eq. 图 3b；`utils.py:188-269`）

三步，全部是纯线性代数，所以折叠后与训练图**逐位等价**：

1. **补齐核尺寸**：把 1×1 / 3×1 / 1×3 用零填充到最大分支的尺寸（`F.pad`），使所有分支
   与最大卷积核同形；
2. **吸收 BN**：`k = (σ²+ε)^-½`（σ² 用 running_var），
   `W_bn = γ·k·W`，`b_bn = γ·k·(b − μ) + β`（代码见 `utils.py:209-210`）——BN 不留下任何推理开销；
3. **压缩并合并**：把 8/10 路权重沿输出通道 concat 成 `W̃`，用 `conv_out` 的权重在通道维
   做一次矩阵乘 `W_final = W_convout · W̃`，偏置同理，得到**一个**普通卷积。

训练图的 concat 宽度（384/480 通道 @600×400，单个激活 ≈460 MB fp32）正是它需要 ~11 GB
显存的原因；折叠后这些全部消失，只剩 6 层卷积、0.919 GMACs。

### 1.3 FST 特征自变换（Eq.3；`utils.py:315-327`）

`FST(x) = Scale·(f ⊙ f) + bias`，其中 `f = block(x)`。代码用两个可学标量实现
（`weight1*f ⊙ weight2*f`），即 `Scale = weight1·weight2`，`bias` 是按通道的 12 维向量。
意义：给纯线性的 MBRConv 序列补一个**二次**项，等价于用 StarNet 式的 square 交互引入
非线性，但推理期只多两次逐元素乘——Table 5 报告它在 UIEB 上比 MUL/Baseline 高 0.65 dB。

### 1.4 HDPA 层级双路注意力（Eq.4–6；`lle.py:28-48`）

```
Ag = Sigmoid(MBRConv1x1(AdaptiveAvgPool2d(F)))          # 全局/通道路
Al = Sigmoid(MBRConv1x1(Max_c(Ag ⊙ F)))                 # 局部路：跨通道取 max 压成 1 通道空间图
F̂  = Ag ⊙ Al ⊙ F
```

复现时最该注意的一点：`Al` 的「MaxPool」在代码里是 `torch.max(x2*x1, dim=1, keepdim=True)`，
即**沿通道维取最大值**，把 H×W×C 压成 H×W×1 再升维，而不是空间池化。这个 1×1 空间 + BN 的
组合直接导致 **batch=1 无法训练**（见 §4 坑 1）。

### 1.5 IWO 增量权重优化（Eq.1–2；`model/utils_IWO.py`）

```
W_final = Frozen(W_pre) + W_learn          # conv_out.weight.requires_grad=False，weight1 可学
y_out   = F_conv1x1(x_concat; W_final) + b_convout
```

官方实现把 `conv_out.weight` 冻成 stage-1 的最优值 `W_pre`，另开一个同形状的 `weight1`
作为 `W_learn`，前向时用 `F.conv2d(x, W_pre + W_learn, bias)`（`utils_IWO.py:50-51`），
`slim()` 里也同样相加（`:135`）。动机是压缩模型训练后期会停滞（Fig.10），调超参收益极低，
于是把「已学到的骨架」钉住，让优化器只学增量。

**这是复现的主要缺口**：官方 `model/lle.py`、`model/isp.py` 一律 `from .utils import ...`，
`model/__init__.py` 从不引用 `utils_IWO`，也没有任何把 stage-1 权重迁移进 `W_pre` 的驱动代码
——也就是说**发布版根本跑不了 IWO**。补建的部分在 `src/mobileie/model.py` +
`engine.transfer_stage1_to_iwo()`。

### 1.6 LVW 局部方差加权损失（Eq.7–10；`loss.py:13-23`）

```
Δ = |out - gt| ;  μ, σ² 在 H×W 上统计
W_Δ = Tanh( |Δ - μ| / (σ + ε) ).detach()
L_LVW = mean(W_Δ ⊙ Δ)
```

直觉：L1 对所有像素等权、L2 对离群点过敏感；LVW 用局部统计量给「偏离均值」的难例像素
升权，同时 Tanh 有界，避免大误差主导。总目标还要再加两项（`loss.py:47`）：
`L = L_LVW + (1 - cos(out.clamp(0,1), gt)).mean() + 2·L_PSNR`，其中 `L_PSNR = (50 - PSNR)/100`。

> 官方实现与公式有一处出入：代码统计的是**带符号残差** `out-gt` 且把 std 除以 √2，
> Eq.7 是先取 L1 幅度再统计。两个版本我都实现了（`loss.pixel: lvw_official | lvw_paper`），
> 默认官方形式，因为发布的权重是它训出来的。

### 1.7 预热阶段（`lle.py:50-54`，`loss.py:26-36`）

`DropBlock(3, p=0.5)` 随机遮输入 → head/body → 两个头同时监督：`tail` 拟合 GT，
`tail_warm` **重构退化输入**，lr=1e-6 跑 10 epoch。效果（推断，非论文原话）：先用自监督把
主干和 BN 的 running stats 标定到真实数据分布上，再进入正常监督，避免一开始就被强梯度冲飞。

### 1.8 训练到底在学什么（把上面几个部件合起来看）

目标函数是纯回归，没有对抗项、没有测试时优化：

```
min_θ  L_LVW(f(x), y) + (1 − cos(f(x).clip(0,1), y)) + 2 · (50 − PSNR(f(x), y))/100
```

输入一张 3×400×600 的退化图，输出同尺寸增强图，监督信号是 LOLv1 里配对的正常曝光照片。
**被更新的只有那 4,075 个数字。**

#### 4,075 个参数分别在学什么

按推理图逐模块拆开（下表相加 = 4,075，与本机 `count_parameters` 实测一致）：

| 位置 | 参数 | 学到的东西 |
|---|---|---|
| head 5×5 (3→12) | 912 | **12 个跨 RGB 的 5×5 空域滤波器** —— 全部"空间知识"的主要来源 |
| head 3×3 (12→12) | 1308 | 12 个响应的二次混合 |
| body 3×3 (12→12) | 1308 | 再一次混合（线性交互深度 = 2） |
| 2 × FST（`Scale` + 逐通道 bias） | 28 | 平方项幅度 + 每通道直流偏移，即亮度曲线的"拐点" |
| PReLU | 12 | 每通道负半轴斜率 |
| HDPA 全局路 1×1 (12→12) | 156 | 由全局均值推出 12 个通道的 sigmoid 增益（"整图多暗 → 各通道提多少"） |
| HDPA 局部路 1×1 (1→12) | 24 | 由逐位置最强响应图推通道增益（局部对比度补偿） |
| tail 3×3 (12→3) | 327 | 12 维特征线性读出为 RGB |

**它不记忆任何场景内容。** 学到的是**一张固定的、带图像自适应的 tone-mapping 算子**：
小邻域滤波 → 平方非线性 → 按全局/局部亮度调通道增益 → 线性读出。
可以粗略理解为「会看全局亮度、并带 5×5 邻域的 3D LUT」。

#### 为什么这点容量就够 23.6 dB：瓶颈不是参数量，是"能不能看邻域"

论文 Table 1（LOLv1 列）本身就排成一条表达力阶梯：

| 方法 | 参数量 (K) | PSNR | 空间邻域 |
|---|---|---|---|
| Zero-DCE | 79.4 | 14.86 | ✗ 逐像素曲线 |
| Zero-DCE++ | 10.6 | 14.68 | ✗ |
| 3D LUT | 593.5 | 17.59 | ✗ 查表 |
| RUAS | 3.44 | 16.40 | 浅 |
| SYELLE | 5.26 | 21.03 | ✓ |
| DDNet | 5,389 | 21.82 | ✓ |
| IAT | 86.9 | 23.38 | ✓ |
| **MobileIE** | **4.05** | **23.62** | ✓ 5×5 大感受野 + 双路门控 |

- 从"纯曲线 14.7 dB"到"4K 参数 23.6 dB"，这 **8.9 dB 的门槛是"能看空域邻域"这件事本身**
  （912 个 5×5 参数是它的载体，但收益要 FST/HDPA/tail 一起兑现 —— 这句是解读，不是论文原话）。
- 反过来，比它大 21 倍的 IAT 只有 23.38，大 1300 倍的 DDNet 只有 21.82
  → 这个任务的天花板由**数据歧义性**（同一张暗图的"正确亮图"不唯一）决定，不由容量决定。
- 各部件的收益也都在 0.3–1.5 dB 量级（论文数字，UIEB 消融）：Table 4 中 L1 22.20 → LVW 22.57；
  Table 5 中无 FST 基线 21.12 → Scale\*MUL 21.95 → 本文 FST 22.60。

#### 那为什么要训 2,000 个 epoch？（这套配法最反直觉处）

不是"485 张图要 2000 遍才学得完"——485 图 × 2000 epoch ≈ 97 万次样本呈现，数据利用早饱和。
**真正原因是这套参数化让优化景观病态：**

1. **训练图有巨量冗余自由度。** 训练时 49,978 参数，concat 宽度 480/384/96 通道再被
   `conv_out` 压回 C。按重参数化的定义，同一个推理函数对应**无穷多组**训练参数。
   本机自检直接证到这点：折叠前后输出差 `2.09e-7`，
   且 `IWO(W_learn=0)` 与 stage-1 模型输出差 **`0.0e+00`**。
2. **梯度大量消耗在"函数等价的无关方向"上**，有用方向推进极慢 → 后期停滞。
   这就是论文 Fig. 10 的现象，也是 IWO 的全部动机：冻结骨架 `conv_out.weight = W_pre`，
   只让残差 `W_learn` 学增量。
3. **并行 BN 锁死尺度**，FST 的平方项又让梯度随激活幅度的平方变化 →
   只能用小学习率 + cosine 反复重启慢慢磨（Sec 4.1：1e-3、每 50 epoch 重置）。
4. **4K 参数必须在像素之间做取舍**，所以给离群像素升权的 LVW 才有那 0.37 dB 的收益。

#### 本机观察到的训练行为（上面解释的证据）

| 观察 | 数值 | 含义 |
|---|---|---|
| warmup 10 epoch：loss 1.517→1.241，但 **val PSNR 仅 1.9–3.2 dB** | stage1 日志 | 预热期主路径被"重构退化输入"的自监督牵着，尚未拉向 GT；不是 bug |
| 正式训练 epoch 1→8：15.15→18.36 dB，其中 epoch 4 回落到 15.91 | stage1 日志 | 4K 参数 + 485 图上的典型抖动，叠加 cosine 衰减 |
| 官方预训练权重在 eval15 上**逐图 PSNR 15.56 ~ 27.94 dB** | `results/eval_pretrained.json` | 最有信息量的一条：它没学到泛化的光照物理模型，只学到 LOLv1 这一分布下的增益曲线，偏离即明显退化 |

**一句话**：训练的不是"看懂暗光"，而是把一个 **4,075 参数、带 5×5 邻域与亮度自适应通道增益的
tone-mapping 算子**，在 LOLv1 这个特定分布上拟合到极限；再用重参数化把训练期的表达冗余完全
消掉，换取推理期零额外开销 —— 这就是"4K 参数"与"0.99 ms"能同时成立的机制。

## 4. 踩坑清单（每条都有实测证据，复现前值得先看）

1. **batch 必须 ≥ 2**。HDPA 把特征压到 1×1 空间图后接 BN，batch=1 时训练直接抛
   `Expected more than 1 value per channel when training, got input size [1,48,1,1]`。
   这也解释了为什么官方 `main.py` 的验证必须在 `net.eval()` 下做。
2. **官方 `main.py:12` 硬编码 `CUDA_VISIBLE_DEVICES='5'`**：单卡机器上这会让 CUDA 直接不可用。
   复现层从不设该变量。
3. **`utils_IWO.py` 用 `xavier_normal_` 初始化 `W_learn`**（`:31-33`），而 Eq.1 的语义是
   `W_pre + W_learn` 应从 `W_pre` 出发。若照搬，stage2 一开始就被噪声扰动。复现层默认
   置零（`model.iwo_learn_init: zero`），并用 `selfcheck.py` 断言置零后 stage2 与 stage1
   输出差为 `0.0e+00`。
4. **PSNR 口径**：论文 23.62 是标准 RGB-PSNR（实测 23.634）；官方 `main.py` 用的是
   逐通道 PSNR 求均值（同一份权重读作 23.959，差 0.32 dB）。对表时要用前者。
5. **LPIPS 骨干**：Table 1 的 0.198 是 **AlexNet** 版（实测 0.1976）；VGG 版同一输出是 0.2934。
6. **LVW 与公式不一致**（见 §1.6），两种都保留、可切换。
7. **数据枚举顺序**：官方用 `os.listdir`（顺序不定、且会把 `.DS_Store` 当图片喂给 PIL 而崩），
   复现层按扩展名过滤 + 排序，保证可复现。
8. **笔记本 GPU 测速不稳定**：有显示负载时同一份权重中位延迟 3.27 ms，空闲时 0.994 ms。
   `measure_latency` 因此同时给 best/median/mean，且最终测速必须在空闲卡上做。
9. **超时长任务要分离进程**：`run_in_background` 的 shell 任务会随会话回收；改用
   `Start-Process cmd.exe /c …cmd -WindowStyle Hidden` 才真正脱离。
10. **Anaconda base 里 `import torch` 触发 `OMP Error #15`**（libiomp5md 重复加载），
    必须用独立 venv 或 `KMP_DUPLICATE_LIB_OK=TRUE`。

---

11. **`run.cmd` 无参数即等于 `start`** —— 我自己在验证守卫时连着误启动过三次 17.8 小时的训练。
    现在 `start` 前有一道「已有链路存活则拒绝」的检查 + 5 秒倒计时（Ctrl+C 可取消）。
    教训：任何能烧掉整晚 GPU 的入口都必须有可取消的确认，不能只靠"我记得没敲"。
12. **PNG 的位深是按内容自动选的，抽样判定位深会误判。** ZRR 的 raw 块 35% 存成 8-bit `L`、
    65% 存成 16-bit `I;16`；我第一版校验器用「max>255 才算真 RAW」，抽 3 个文件恰好全 16-bit
    就放行了，换一批抽样就会误判成污染。正确判据是**有没有饱和在容器上限**（8-bit 那批
    只有 1% 恰好 =255，且 16-bit 那批 0% ≤255，两者互补 → 无损）。`verify_dataset.py --raw` 已改。
